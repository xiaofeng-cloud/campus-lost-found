# 校园失物招领信息管理系统设计说明

## 建设目标

面向在校师生建设一套可直接演示的校园失物招领系统。普通用户可以注册登录、发布失物或招领信息、检索信息、发起认领并跟踪处理结果；管理员可以审核内容、管理认领流程、查看统计数据和操作记录。

## 约束与原则

- 前后端分离，后端使用 Java 17、Spring Boot 3.5 和 MySQL，前端使用 Vue 3、TypeScript 与 Vite。
- 所有用户可见文本、接口提示、数据库注释和项目文档均使用中文。
- 首版围绕“发布—检索—认领—确认归还—后台监管”形成完整闭环。
- 密码必须加密保存，接口使用 JWT 鉴权，普通用户不能调用管理员接口。
- 测试环境使用 H2，生产与演示环境使用 MySQL，避免测试依赖本机数据库。

## 方案比较

### 方案一：单体前后端分离（采用）

一个 Spring Boot 服务承载业务接口，一个 Vue 单页应用承载用户端和管理端。部署简单、结构清晰，适合个人毕设的开发周期和答辩环境。

### 方案二：微服务

将用户、物品、认领和通知拆成多个服务。扩展性更强，但部署、事务、日志和服务治理成本远超本项目实际需要，因此不采用。

### 方案三：服务端模板渲染

后端直接生成页面，初期文件更少，但不符合指定的 Vue 3 技术路线，也不利于展示前后端分离能力，因此不采用。

## 业务角色

- 游客：浏览已通过审核的信息，进行搜索和筛选。
- 普通用户：注册登录、发布信息、维护自己的信息、申请认领、处理收到的认领申请、查看通知。
- 管理员：审核或驳回信息、查看系统统计、查看操作日志。

## 核心流程

1. 用户注册并登录。
2. 用户发布失物或招领信息，状态进入“待审核”。
3. 管理员审核通过后，信息进入“寻找中”。
4. 其他用户提交认领申请，发布者查看申请并同意或拒绝。
5. 同意后信息进入“认领中”，线下核验完成后发布者确认归还。
6. 信息进入“已找回”，相关用户收到站内通知，关键操作写入日志。

## 数据模型

- 用户：账号、昵称、密码摘要、手机号、角色、状态、创建时间。
- 物品信息：类型、标题、描述、分类、地点、发生时间、联系方式、图片地址、状态、发布人、审核意见。
- 认领申请：关联物品、申请人、证明说明、状态、处理意见和处理时间。
- 通知：接收人、标题、内容、已读状态和创建时间。
- 操作日志：操作者、操作类型、目标类型、目标编号、操作说明和时间。

## 界面范围

- 门户首页：校园主题视觉、关键字搜索、类型与分类筛选、最新信息卡片。
- 登录与注册页。
- 信息发布页和详情页。
- 个人中心：我的发布、我的申请、收到的申请和通知。
- 管理后台：数据概览、待审核列表和操作日志。

## 非目标

- 首版不接入短信、邮件、微信或校园统一身份认证。
- 首版不实现实时聊天、地图定位、对象存储和复杂推荐算法。
- 图片暂以可访问的 URL 保存，避免把文件存储问题混入核心业务闭环。

## 验收标准

- 后端自动化测试通过并可构建为可执行 JAR。
- 前端测试与生产构建通过。
- MySQL 初始化脚本、中文 README、接口说明和部署步骤齐全。
- 普通用户和管理员的核心流程均可从界面完成。
